## What already exists

`github.com/manuaishika/interior-design`, branch
`claude/interior-design-room-analysis-yj4fvg`. It is a working FastAPI backend
plus a five-page frontend, 264 tests passing.

```
app/
  main.py          endpoints: /api/read /api/generate /api/chat /api/designs
  config.py        settings + which engine runs (resolve_backend)
  pipeline.py      the flow: read -> lock -> mask -> draw
  reading.py       GPT-4o reads the room, and the not-a-room gate
  openai_images.py the one-key engine: GPT-4o finds doors, gpt-image edits
  google_ai.py     the free engine (Google AI Studio, no card)
  segmentation.py  SAM2 via Replicate
  generation.py    prompts, style presets, ROOM_BRIEFS
  imaging.py       mask geometry — build_inpaint_mask is the important one
  auth.py store.py accounts, sessions, saved designs
static/showcase.html   the whole frontend, one file
docs/index.html        a copy of it, served by GitHub Pages
```

Three engines, chosen automatically from whichever keys are present:

| keys set | engine | doors and windows |
| --- | --- | --- |
| `GOOGLE_API_KEY` | free | *asked* to stay put |
| `OPENAI_API_KEY` | openai | **masked** — boxes from GPT-4o |
| `OPENAI_API_KEY` + `REPLICATE_API_TOKEN` | hosted | **masked** — outlines from SAM2 |

## Update: it has now run for real (2026-09-11)

The claim below used to be true and is not any more — leaving it in case a
future session works from a container that is network-blocked again and needs
the same warning.

On a real, org-verified OpenAI key: `/api/generate` on the `openai` engine
produced two real Scandinavian-living-room options from a real photo, the
window held in place. Separately, `to_openai_mask`'s convention was checked
with a synthetic probe (a solid red square marked "preserve" against a plain
background, asked to repaint the rest as a meadow) — the square came back
byte-for-byte in place, confirming gpt-image-2.5-sunburst's edit endpoint
honours the alpha mask exactly, not as a soft suggestion. `looks_inverted`
never fired. The mask convention is settled: **not inverted**,
`INVERT_INPAINT_MASK` stays `false`.

One real finding from that run: GPT-4o's structure boxes can be looser than
useful (a floor-to-ceiling window boxed as most of the frame). `FIND`'s
wording was tightened in response — see `app/openai_images.py`'s docstring on
`FIND` for the current rule. Re-check box tightness on a few more real photos,
especially ones with an actual door, before trusting it unwatched.

### What was true before this ran, for a future blocked container

No image had ever been generated by this pipeline. The container it was
written in had no outbound network, so every call to OpenAI, Google and
Replicate was stubbed in tests and had never run for real. Everything between
the upload and the API call was real, tested code; the API calls themselves
were unproven. If you find yourself in that position again: assume the first
live run will fail on something small, and do not assume the code is right
because the tests pass — get a live key run before trusting quality claims.

## First job: make one image, once

Locally, not deployed:

```bash
git clone https://github.com/manuaishika/interior-design
cd interior-design
git checkout claude/interior-design-room-analysis-yj4fvg
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
echo "OPENAI_API_KEY=sk-..." > .env
.venv/bin/uvicorn app.main:app --reload
```

Then, in another terminal:

```bash
curl -s localhost:8000/api/health | python3 -m json.tool
# want: "engine": "openai", "can_read": true, "can_draw": true

curl -X POST localhost:8000/api/generate \
  -F photo=@a-real-room.jpg -F style=japandi -F room_type=bedroom \
  -o out.json
python3 -c "
import json,base64
d=json.load(open('out.json'))
open('design.png','wb').write(base64.b64decode(d['generations'][0]['image_base64']))
open('mask.png','wb').write(base64.b64decode(d['generations'][0]['inpaint_mask_base64']))
print('wrote design.png and mask.png')"
```

Open both. **Check the mask before judging the picture** — white is what was
repainted, black is what was protected. If the doorway is white, the mask is
backwards.

### The mask convention is the known unknown

`app/openai_images.py:to_openai_mask` converts our mask (white repaints) to
OpenAI's. The documentation says both "white areas are replaced" and "the
alpha channel decides", and getting it backwards **raises no error at all** —
it repaints the doorway and carefully preserves the sofa.

There is a detector (`looks_inverted`) that logs a warning when the locked
regions changed more than the editable ones. If you see that warning, or the
output has a mangled door, set `INVERT_INPAINT_MASK=true` and run again.
Settle this empirically on the first run and write down which way it goes.

## Second job: whatever the first job breaks

Likely candidates, in order:

1. **403, organisation not verified.** Image models need a one-time ID check,
   separate from billing. platform.openai.com/settings/organization/general →
   Verify Organization → wait ~15 min. Reading rooms works without it, so only
   the picture step fails, which looks like the app being broken.
2. **insufficient_quota.** Credit belongs to an *organisation*, not a person.
   A key made in your own org cannot spend credit sitting in the client's org.
   Check platform.openai.com/settings/organization/billing and make the key
   inside whichever org holds the money.
3. **model_not_found.** `openai_images.IMAGE_MODELS` is a fallback chain
   (`gpt-image-2.5-sunburst`, `gpt-image-2`, `gpt-image-1`). If the ids have
   moved again, fix the chain.

`app/openai_images.py:explain` already turns these into plain sentences. If a
new failure is not covered, add it there rather than at the call site.

## House rules for this codebase

- **Tests are behavioural.** They pin what must stay true and why, not
  implementation. Read a few before writing any.
- **Never commit a key.** `.env` is gitignored; `render.yaml` uses
  `sync: false` so keys are typed into the host.
- Comments explain *why*, especially where something is deliberately weird.
  There are several such places; leave those comments intact.
- `static/showcase.html` and `docs/index.html` are the same file. Change one,
  copy to the other. `docs/` has exactly one deliberate difference, a status
  line — check `git diff` before overwriting.
- Run `.venv/bin/python -m pytest` before every commit. 264 pass right now.

## Do not

- Do not split the backend into another repository yet. It already exists
  here, wired to the frontend and to the tests. A second repo means two
  deploys, two sets of keys, CORS, and duplicated models — pay that cost when
  there is a reason, not before.
- Do not add a new engine. Three is already one more than the product needs.
- Do not rewrite the frontend. It is one file on purpose so it can be served
  by anything.

## Ask for

More real generated rooms, and the mask beside each — especially rooms with
an actual door in frame, which the first live run did not have. Box
tightness on doors specifically is still unverified; the window case that was
checked is now known-good.
